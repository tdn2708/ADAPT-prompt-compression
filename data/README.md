# Data: pick-and-place feasibility in the (G, K, D, A) model

Generated by `python -m adapt.generate` (seed 0, about 20 s on a CPU; the output is identical on every run).
Statistics and reference points without a language model: `REPORT.md`. Independent audit: `AUDIT.md` and `AUDIT_X4.md`.
Prompt levels and token counts: `PROMPTS.md`. Hand check of 30 rows: `HAND_CHECK.md`.

## One row

```json
{"id": "train/0", "split": "train",
 "G": {"object": "picture frame", "from": "cabinet", "to": "nightstand",
       "text": "Please move the picture frame that's sitting on the cabinet onto the nightstand."},
 "K": {"context": ["..."], "fields": {"reach_pick": "...", "...": "..."},
       "rules": {"payload": "The robot can lift objects of at most 1.06 kg.", "...": "..."},
       "masses": {"laptop": 1.96, "potted plant": 1.46, "cup": 0.29, "picture frame": 0.98, "thermos": 0.68},
       "masses_text": "Known object masses: ...",
       "limits": {"payload": 1.06, "reach": 0.6, "height": 0.83, "clearance": 0.29, "energy": 0.8, "reserve": 22}},
 "D": {"reach_pick": 0.58, "reach_place": 0.28, "place_height": 0.56, "clearance": [0.66, 0.71, 0.93, 1.56, 1.64, 1.26],
       "route_length": 35.6, "battery": 84},
 "A": {"feasible": true, "action": "Execute", "violated": [],
       "plan": "go to the cabinet, pick up the picture frame, drive to the nightstand, put the picture frame down",
       "explanation": "Every limit holds; the tightest is reach_pick (3% to spare)."},
 "key_rule": "payload", "slack": {"payload": 0.0755, "reach_pick": 0.0333, "...": "..."}, "flip_margin": 0.0333, "near": true,
 "n_violated": 0, "catalog_size": 5, "n_readings": 6, "k_dependent": true}
```

G is the user goal, K the prior world knowledge (the rules and the known masses), D the dynamic data from the sensors and
A the action. The six rules of this row, worked by hand:

- payload: picture frame 0.98 kg <= 1.06 kg (7.5% to spare);
- reach_pick: 0.58 <= 0.6 m (3.3% to spare, the tightest);
- reach_place: 0.28 <= 0.6 m;
- height: nightstand 0.56 <= 0.83 m;
- clearance: narrowest point 0.66 >= 0.29 m;
- battery: 84 >= 0.8 x 35.6 + 22 = 50.5.

All six hold, so the answer is feasible. The fields after A (`key_rule`, `slack`, ...) are metadata for the analysis;
the model never sees them.

## How a row is made

1. Vocabulary: 96 request templates, 32 objects and 20 places for train, val and test; `unseen` uses 32 templates,
   8 objects and 5 pick-up places that never appear elsewhere.
2. Pick a pattern: the answer (feasible or not) and a key rule, spread evenly over the 12 combinations. In a feasible row
   the key rule is near its threshold with probability 0.5; in an infeasible row the key rule fails, plus 0, 1 or 2
   other rules (probability 0.60, 0.25, 0.15). Every other rule holds with any slack, the same for both answers, so the
   rules that do not decide never give the answer away.
3. Draw every quantity from its fixed distribution and repeat until the slack falls in the band of the pattern. The
   pattern only decides which draws are kept; it never edits a number.
4. Compute A by the rules from the rounded numbers. A must match the pattern, and no slack may be below 1%.
5. Pass one validity check (`adapt/verify.py`) for G, K, D and A. No D is used twice in the whole dataset.

## Files

| File | Rows | Use |
|---|---|---|
| `train.jsonl` | 2,400 | training; 200 rows per (answer, key rule) |
| `val.jsonl` | 480 | checkpoint selection |
| `test.jsonl` | 960 | main results, scored once |
| `near_threshold.jsonl` | 480 | near-threshold: the deciding rule is within 5% of its threshold and is the only deciding rule |
| `d_pairs.jsonl` | 400 | D pairs: 200 pairs with the same G and K, one reading of D crosses the threshold |
| `k_pairs.jsonl` | 420 | K pairs: 210 pairs with the same G and D, one limit of K changes |
| `g_pairs.jsonl` | 400 | G pairs: 200 pairs with the same K and D, only the requested object changes (two objects of similar mass, so only the catalog of K decides) |
| `unseen.jsonl` | 480 | unseen: templates, objects and pick-up places never seen in training |
| `longer_than_train.jsonl` | 240 | longer than train: catalogs of 8 objects and 16 clearance readings (train has at most 5 and 8) |
| `free_form.jsonl` | 204 | free-form: test requests reworded freely instead of by the templates (`tools/make_paraphrase.py`; the wordings were written by a large language model) |
| `llmlingua2.jsonl` | | the full prompt of every test row compressed by LLMLingua-2 (`tools/make_lingua.py`) |
| `train_x4.jsonl` | 9,600 | 4 times the training data, same recipe (audited in `AUDIT_X4.md`) |
